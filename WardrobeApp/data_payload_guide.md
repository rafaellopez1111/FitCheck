# WardrobeApp: Payload Reference

## Conventions

- All field names use snake_case.
- Every request has an **envelope** (`user_id`, `entity`, `action`) and, depending on the action, a `data` object.
- `id` is generated by the app on create and required on get_one, update, and delete.
- `get_all` has no `data`.
- Audit fields (`created_on`, `created_by`, `updated_on`, `updated_by`) are set by the system, never typed by the user.
- Dates use ISO 8601 UTC, e.g. `2026-10-30T14:05:00Z`.
- Id prefixes: `c_` clothing, `w_` wishlist, `o_` outfit, `u_` user/profile.

## Entities and actions

| Entity | create | get_one | get_all | update | delete | Special |
|---|---|---|---|---|---|---|
| clothing | yes | yes | yes | yes | yes | none |
| wishlist | yes | yes | yes | yes | yes | mark_as_bought |
| outfit | yes | yes | yes | yes | yes | none |
| profile | yes | yes | no | yes | yes (reset) | none |

## Fields per entity

| Entity | Required | Optional | Audit (system-set) |
|---|---|---|---|
| clothing | name, category | photo, brand, size, style, notes | created_on, created_by, updated_on, updated_by |
| wishlist | name, category | photo, brand, size, style, notes, price, store_link, priority | same |
| outfit | name, item_ids | occasion, notes | same |
| profile | name | photo | same |

Categories: Camisa, Camiseta, Blusa, Casaco, Calça, Shorts, Vestido, Saia, Sapato, Tênis, Chinelo, Bota, Sandália, Acessórios
Styles: Casual, Formal, Esportivo, Social, Streetwear, Festa, Praia (optional; if sent, must be in this list)
Priority values: low, medium, high

## 1. CLOTHING

### create
```json
{
  "user_id": "u_001",
  "entity": "clothing",
  "action": "create",
  "data": {
    "name": "Blue denim jacket",
    "category": "Casaco",
    "photo": "file:///path/jacket.jpg",
    "brand": "Levi's",
    "size": "M",
    "style": "Casual",
    "notes": "Bought in 2023"
  }
}
```

### get_one
```json
{
  "user_id": "u_001",
  "entity": "clothing",
  "action": "get_one",
  "data": { "id": "c_001" }
}
```

### get_all
```json
{
  "user_id": "u_001",
  "entity": "clothing",
  "action": "get_all"
}
```
Returns a summary of each item: id, name, category, photo, brand.

### update
```json
{
  "user_id": "u_001",
  "entity": "clothing",
  "action": "update",
  "data": {
    "id": "c_001",
    "size": "L"
  }
}
```
Send only the fields that changed.

### delete
```json
{
  "user_id": "u_001",
  "entity": "clothing",
  "action": "delete",
  "data": { "id": "c_001" }
}
```
Side effect: the id is also removed from `item_ids` in every outfit that uses it.

### update

```json
{
  "user_id": "u_001",
```

```json
  "user_id": "u_001",
  "entity": "wishlist",
  "action": "delete",
  "data": { "id": "w_001" }

```

### mark_as_bought (special action)
```json
{
  "user_id": "u_001",
  "entity": "wishlist",
  "action": "mark_as_bought",
  "data": { "id": "w_001" }
}
```
What it does:
1. Creates a clothing item copied from the wishlist item (name, category, photo, brand, size, notes). Price, store_link, and priority are not copied.
2. The new clothing item gets a new id (`c_...`) and fresh created_on / created_by.
3. Deletes the wishlist item.
4. Returns the newly created clothing item.

## 3. OUTFIT

### create
```json
{
  "user_id": "u_001",
  "entity": "outfit",
  "action": "create",
  "data": {
    "name": "Casual Friday",
    "item_ids": ["c_001", "c_004", "c_007"],
    "occasion": "Work",
    "notes": "Works with the grey scarf"
  }
}
```
Validation: every id in `item_ids` must exist in clothing, and the list must not be empty.

### get_one
```json
{
  "user_id": "u_001",
  "entity": "outfit",
  "action": "get_one",
  "data": { "id": "o_001" }
}
```
Returns the outfit with its items resolved (full clothing objects instead of only ids).

### get_all
```json
{
  "user_id": "u_001",
  "entity": "outfit",
  "action": "get_all"
}
```
Returns a summary of each outfit: id, name, occasion, item_ids (used to show thumbnails).

### update
```json
{
  "user_id": "u_001",
  "entity": "outfit",
  "action": "update",
  "data": {
    "id": "o_001",
    "name": "Casual Friday v2",
    "item_ids": ["c_001", "c_004"]
  }
}
```
`item_ids` replaces the whole list, so send the full new list, not only the changes.

### delete
```json
{
  "user_id": "u_001",
  "entity": "outfit",
  "action": "delete",
  "data": { "id": "o_001" }
}
```
The clothes in the outfit are not touched.

## 4. PROFILE

One profile per user, so there is no get_all.

### create
```json
{
  "user_id": "u_001",
  "entity": "profile",
  "action": "create",
  "data": {
    "name": "Maria",
    "photo": "file:///path/me.jpg"
  }
}
```

### get_one
```json
{
  "user_id": "u_001",
  "entity": "profile",
  "action": "get_one",
  "data": { "id": "u_001" }
}
```
Also returns calculated stats: total clothes, total outfits, total wishlist items, total wishlist price. These are computed, not stored.

### update
```json
{
  "user_id": "u_001",
  "entity": "profile",
  "action": "update",
  "data": {
    "id": "u_001",
    "name": "Maria Silva"
  }
}
```

### delete (reset all data)
```json
{
  "user_id": "u_001",
  "entity": "profile",
  "action": "delete",
  "data": { "id": "u_001" }
}
```
Side effect: deletes the profile and all clothing, wishlist, and outfit items. Ask the user for confirmation first.

## Database schema

Types are written in SQL style (SQLite works well on the phone). If you stay with AsyncStorage, each table becomes one JSON collection with the same fields.

Shared audit columns on every table: `created_on`, `created_by`, `updated_on`, `updated_by` (all NOT NULL, set by the system).

### outfit_item (join table for outfit.item_ids)
| Column | Type | Constraints | Notes |
|---|---|---|---|
| outfit_id | TEXT | NOT NULL, FK -> outfit.id ON DELETE CASCADE | |

### Relationships
| From | To | Type |
|---|---|---|
| profile | clothing, wishlist, outfit | one-to-many |
| outfit | clothing | many-to-many via outfit_item |

### Suggested indexes
- clothing(user_id, category)
- wishlist(user_id, priority)
- outfit(user_id)
- Sorting by created_on DESC on each table

## Response format

Every response has the same four fields, in this order: `code`, `success`, `message`, `data`.

| Field | Type | Notes |
|---|---|---|
| code | number | Status code, always first. 200 on success. |
| success | boolean | true when code is 200, false otherwise |
| message | string | Short human-readable text, always present |
| data | object, array, or null | The result. null on errors. |

### Success: single item (create, get_one, update, mark_as_bought)
```json
{
  "code": 200,
  "success": true,
  "message": "Clothing item retrieved successfully",
  "data": {
    "id": "c_001",
    "name": "Blue denim jacket",
    "category": "Casaco",
    "photo": "file:///path/jacket.jpg",
    "brand": "Levi's",
    "size": "M",
    "style": "Casual",
    "notes": "Bought in 2023",
    "created_on": "2026-10-30T14:05:00Z",
    "created_by": "u_001",
    "updated_on": "2026-10-30T14:05:00Z",
    "updated_by": "u_001"
  }
}
```

### Success: list (get_all)
```json
{
  "code": 200,
  "success": true,
  "message": "Clothing items retrieved successfully",
  "data": [
    { "id": "c_001", "name": "Blue denim jacket", "category": "Casaco", "photo": "file:///path/jacket.jpg", "brand": "Levi's" }
  ]
}
```
An empty list returns `"data": []` with code 200, not an error.

### Success: delete
```json
{
  "code": 200,
  "success": true,
  "message": "Clothing item deleted successfully",
  "data": { "id": "c_001" }
}
```

### Error
```json
{
  "code": 404,
  "success": false,
  "message": "Clothing item c_999 does not exist",
  "data": null
}
```

### Codes
| Code | success | When |
|---|---|---|
| 200 | true | Any action completed |
| 400 | false | Validation error: missing name or category, empty item_ids, missing required `data` |
| 404 | false | Unknown id |
| 405 | false | Action not supported for that entity (e.g. get_all on profile) |
| 500 | false | Storage error (could not read or write the phone storage) |
